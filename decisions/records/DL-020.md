## Context

The demo site (DL-013) is a placeholder. A hosted example needs a matching set of SVG pages, MP3 and position files from one MuseScore export of an open-licensed score; mixing exports does not work (MuseScore 4.6.2 and 4.7 write SVGs in different units, for one). Such a set is not in the repository yet.

## Decision

The demo becomes **"Try it with your own export"**: the visitor picks the files of one MuseScore export (the SVG pages, the audio, the `.mpos` and optionally the `.spos`), and the page plays them in a `<segno-player>` with controls and follow on. The files never leave the browser (object URLs). Pages are ordered by the page number in their names (`song-1.svg`, `song-2.svg`, …).

A hosted example score is added next to it once a matching, open-licensed export set is in the repository, listed in `fixtures/SOURCES.md` (DL-008).

The demo loads the player from the built package files, which `npm run build:demo` copies into the site (`site/segno/`); `npm run demo` builds it and serves it locally with Vite.

## Rationale

The own-files demo needs no hosted score, shows the export workflow in the README end to end, and stays useful after an example is added: it is how someone checks their own score before putting it on a site.

## Consequences

- Building the demo now builds the package first.
