## Context

The demo site (DL-013) needs to work without requiring a visitor to export and select files first. A hosted example needs a matching set of SVG pages, MP3 and position files from one MuseScore export of an open-licensed score; mixing exports does not work (MuseScore 4.6.2 and 4.7 write SVGs in different units, for one).

## Decision

The demo initially loads **När juldagsmorgon glimmar**, a bundled example from Fria Noter, in a `<segno-player>` with controls and follow on. Playback starts only when the visitor presses play. The native `.mscz` source and its matching SVG, MP3, `.mpos` and `.spos` exports live in `fixtures/nar-juldagsmorgon-glimmar/`, listed in `fixtures/SOURCES.md` (DL-008), and are copied into `site/scores/` at build time. The page links to Fria Noter, CC BY 4.0 and the source score, and identifies the tempo adjustment to 103.5 BPM. The tempo is changed in the score itself before export; the player's playback rate remains 100%.

**"Try it with your own export"** remains available in an expandable section: the visitor picks the files of one MuseScore export (the SVG pages, the audio, the `.mpos` and optionally the `.spos`), and the same player switches to them. The files never leave the browser (object URLs). Pages are ordered by the page number in their names (`song-1.svg`, `song-2.svg`, …). A button returns to the bundled example. Its credit is shown only while that example is selected. An incomplete file selection leaves the current score intact and reports the missing files.

The demo loads the player from the built package files, which `npm run build:demo` copies into the site (`site/segno/`); `npm run demo` builds it and serves it locally with Vite.

## Rationale

A bundled example lets anyone try playback immediately, including on phones. Keeping the own-files workflow alongside it lets someone check their own score before putting it on a site. Committing the native score makes the example reproducible without a MusicXML round trip; the older position-only test fixtures remain unchanged.

## Consequences

- Building the demo builds the package first and copies the committed score exports; it does not need MuseScore installed.
