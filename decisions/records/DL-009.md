## Context

The sync map (DL-003) holds positions and times; a player needs answers to "what is playing now", "where should the note cursor be", "what was clicked" and "where do I seek". The prototype's answers were tuned on real scores with repeats; these are its behaviours.

## Decision

`createTimeline(sync)` provides:

- **`at(ms, endMs)`**: binary search for the last event at or before `ms` → `{ event, bar, page, box, progress, note }`. Before the first event it reports the first bar (with progress 0), so a player shows where playback will start. `progress` is how far into the bar playback is, using the next event's time, or `endMs` (the audio's duration) for the last bar; without `endMs` the last bar stays at 0. It returns null only for a map with no events.
- **`noteAt(ms, endMs)`**: the note cursor `{ page, x, y, h }`. Between a note and the next one played, if that next note is on the same system (same page, y within 0.002 of the page height) and further right, x moves linearly in time from one to the other, arriving as the second sounds. Otherwise (the last note of a line, or before a repeat jumps back) it moves on to the right edge of the bar holding the note, then jumps. A note that lies in no bar stays where it is.
- **`barAtPoint(page, fx, fy)`**: the bar whose box contains a point (in page fractions), or -1.
- **`seekTimeForBar(bar, nowMs)`**: a bar inside repeats plays several times; take the occurrence closest to the current position, so clicking a bar within a repeat stays in the same pass. -1 if the bar never plays.
- **`eventIndexAt(ms)`**: the event index alone.

**Note positions.** An `.spos` segment's x is where its noteheads start, and its width is its widest element, so accidentals and clusters make it wider than the notehead. `buildSync` places each note at x plus half a typical notehead, the typical notehead being the 10th percentile of all segment widths in the score: narrow segments are plain notes; wide ones carry accidentals or clusters.

## Rationale

- Moving the cursor evenly between notes gives the eye a continuous line to follow instead of a jump per note, and arriving as each note sounds keeps it honest about the beat.
- Running on to the barline at a line's end (instead of gliding backwards or across to the next line) reads as "this line is done" before the jump.
- Picking the nearest pass in `seekTimeForBar` matches what a reader means when clicking inside a repeat they are listening to.
- The 10th percentile is robust to scores full of accidentals while still close to a plain notehead's width.

## Consequences

- `.spos` segments span all voices and staves, so the cursor also stops at rests and at notes in the accompaniment. Grace notes are not separate segments.
- The notehead estimate is approximate; a score where nearly every segment carries accidentals would place the cursor slightly right of the noteheads.
- `barAtPoint` and `seekTimeForBar` are linear scans, which is fine for the few hundred bars and events of a song.
