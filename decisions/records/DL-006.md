## Context

A prototype of the player was tuned by ear on real scores (songs with repeats, voltas, fermatas and tempo changes, on desktop and phone). Several marker designs were tried:

- a bar marker that slid between bars, with a darker "already played" fill: it felt jumpy;
- a bar-wide band gliding through each system: it lost the sense of the bar;
- a first marker that slid about 140 ms into each bar: it felt late, even though MuseScore's audio itself sounds ~60 ms after the event times (DL-002).

## Decision

`<segno-player>` (DL-005) draws two markers, with these defaults:

| Part | Design | Values |
|---|---|---|
| Bar marker | A static light tint over the whole system height, reaching a little into the neighbouring bars and fading out at the sides (a CSS mask), multiplied over the page so the notes stay black. It crossfades from bar to bar, or switches at once with `bar-change="jump"`. | Tint 7% of the accent colour; overlap 1.2% of the page width each side; crossfade 90 ms in, 260 ms out |
| Note cursor | A thin line through the system that moves every frame, evenly from note to note, reaching each as it sounds, and on to the barline at a line's end (DL-009) | 2 px, accent at 55%, multiplied |
| Leads (relative to event times) | The bar marker changes slightly early, so its fade-in reaches full strength about as the note sounds. The note cursor has no fade and arrives with the event. | Bar +20 ms, note 0 ms, both scaled by the playback rate |
| Interaction | Click a bar to play from it (the nearest pass inside repeats); follow-scroll brings an off-screen system to about a quarter from the top, smoothly unless reduced motion is requested | Tempo 50–150% via `playbackRate`, pitch preserved |

Both leads are configurable (`bar-lead`, `note-lead`).

## Rationale

The static tint keeps the bar readable (the notes stay black under a multiply blend) and marks where the music is without moving; the note cursor gives the eye something to follow between bar changes. With the bar marker at +20 ms, a note cursor with the same lead looked early, so it has none. Audio devices add their own latency (Bluetooth adds a lot), so no fixed lead suits everyone.

## Consequences

- The values are defaults, not constants: sites tune them through attributes and CSS custom properties.
- The markers are judged by ear and eye; changes to them should be tried on real scores with repeats before they are made.
