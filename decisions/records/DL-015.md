## Context

Sites must be able to make the player fit their design: colours, spacing, the controls' look and density, and how strong the markers are. Custom properties inherit through the shadow boundary (DL-014), so they are the natural theming interface for a web component. Size container queries are supported in all current browsers; container style queries on custom properties became supported in every engine in May 2026 (Firefox 151; Chrome since 111, Safari since 18).

## Decision

**CSS custom properties are the public theming API.** Each is documented with its default in `docs/theming.md`. Defaults live in `var(--segno-…, default)` fallbacks inside the shadow styles, never on `:host`, so values set anywhere on the page (on `segno-player`, a class, `:root`) inherit and win.

| Property | Default | Controls |
|---|---|---|
| `--segno-accent` | `#b3261e` | The marker and cursor colour, and the controls' accent |
| `--segno-bar-strength` | `7%` | The bar marker's tint |
| `--segno-bar-fade-in` / `--segno-bar-fade-out` | `90ms` / `260ms` | The bar marker's crossfade |
| `--segno-cursor-width` / `--segno-cursor-strength` | `2px` / `55%` | The note cursor |
| `--segno-page-gap` | `1rem` | Space between pages |
| `--segno-page-background` / `--segno-page-shadow` | white / a soft shadow | The pages' sheet |
| `--segno-controls-background` / `--segno-controls-color` | `#1d1c1a` / `#fff` | The built-in controls |
| `--segno-controls-radius` / `--segno-controls-gap` | `1.125rem` / `1.125rem` (narrow: `0.5rem`) | The built-in controls' shape |
| `--segno-font` | `inherit` | The controls' font |

- **`::part()`** names are stable API for structural styling: `pages`, `page`, `page-image`, `note-cursor`, `bar-marker`, `controls-area`, `controls`, `play-button`, `restart-button`, `time`, `current-time`, `duration`, `seek`, `settings-button`, `settings`, `tempo`, `tempo-decrease`, `tempo-value`, `tempo-increase`, `follow`, `follow-input`.
- **The player is a size container** (`container: segno-player / inline-size`), so the built-in controls lay out by the player's width, not the viewport's. Sites can target the player in their own container queries as well.
- **Presets through container style queries**, as an enhancement: setting `--segno-controls: compact` reduces the built-in controls to the play button and the seek slider on one line, and `--segno-markers: strong` doubles the bar marker's tint and strengthens the note cursor. Browsers without style queries ignore the presets and keep the defaults; everything else works.
- The controls default to a dark bar with light text on both light and dark sites, keeping them distinct from the engraved pages. Sites can override the background and foreground, including with `light-dark()` values if they want scheme-dependent colours.

## Rationale

Variables cross the shadow boundary, cascade like any CSS, and can be scoped by any selector or query on the site, which makes them the most flexible and least surprising theming surface. Keeping defaults in fallbacks avoids the trap where `:host` declarations override inherited values. Style-query presets let one variable switch a coordinated set of values, and they degrade to the defaults.

## Consequences

- Renaming or removing a variable or part is a breaking change, released with semver (DL-012).
- New presets are cheap to add, but each must look right without style query support.
