## Context

DL-011 planned Playwright browser tests for the element. The player needs a real browser: custom elements, shadow DOM, layout, `<audio>`. A second test runner would split the coverage floor in two.

## Decision

The element is tested with **Vitest's browser mode**, running Chromium through Playwright (`@vitest/browser-playwright`). One `vitest` command runs two projects: `core` in Node and `player` in Chromium, and their coverage is merged against the same 90% floor.

The tests need no real score: a blank SVG page with the fixture's page size and a generated silent WAV of the right length (both as blob URLs) are enough to drive loading, seeking, events and marker positions with the fixture's positions files. Chromium runs with autoplay allowed.

CI installs Chromium for Playwright; locally, `CHROMIUM_PATH` can point Playwright at an existing Chromium.

## Rationale

One runner, one config and one coverage number, with the element tested where it runs. Synthetic pages and audio make the tests fast and independent of any score's licence.

## Consequences

- Firefox and WebKit can be added as more browser instances when the player approaches 1.0 (the milestone's browser coverage).
- Tests that depend on real playback timing are avoided; they seek and assert instead.
