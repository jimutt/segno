## Context

DL-010 expected a bundler step for a single-file browser build, and DL-005's draft loaded `dist/segno-player.js` from a CDN. The player is small, has no dependencies, and is written as ES modules like the core.

## Decision

**ES modules only, no bundler, for now.** `tsc` builds the player like the core, and the package exports it as `segno/player`; importing it defines `<segno-player>` (once, if not already defined). The package's `sideEffects` lists the player's entry module.

Without a build step on the site, it loads straight from a CDN, which serves the modules and their relative imports as they are:

```html
<script type="module" src="https://cdn.jsdelivr.net/npm/segno/dist/player/index.js"></script>
```

The build keeps the core DOM-free: the core is compiled against the ES library alone (DL-004), the player in a second pass with the DOM library.

A single-file bundle may be added later as an alternative next to the modules, if sites need one; it would not replace them.

## Rationale

The modules are a handful of small files, which HTTP/2 serves about as fast as one; skipping a bundler keeps the toolchain to `tsc` and the published code identical to the source. Sites with their own bundler import `segno/player` as usual.

## Consequences

- The CDN URL is `dist/player/index.js`, not DL-005's `dist/segno-player.js`.
- The size budget (DL-011) gains an entry for the player.
