## Context

Sites that would use Segno range from static site generators and framework apps to WordPress pages. A player tied to one framework would shut most of them out, and asking every site to wire up the core, an `<audio>` element and an overlay by hand would make Segno hard to adopt.

## Decision

The main integration is `<segno-player>`, a framework-free custom element: a script tag and the element, and the pages play.

A first draft of its API, **to be settled with the maintainer before it is built**:

```html
<script type="module" src="https://cdn.jsdelivr.net/npm/segno/dist/segno-player.js"></script>
<segno-player
  pages="song-1.svg song-2.svg"
  audio="song.mp3"
  positions="song.mpos"
  notes="song.spos"
  controls>
</segno-player>
```

- **Inputs:** file URLs (the element fetches them and builds the sync map in the browser; it needs the SVGs' viewBoxes), or a prebuilt sync map (`sync="song.sync.json"` or a `sync` property) for sites that build it ahead.
- **Options:** `bar-lead` and `note-lead` (ms), `note-cursor` (on/off), `bar-change` (fade/jump), `follow` (scroll to the next system), `controls` (built-in player bar).
- **Methods and events:** `play()`, `pause()`, `seek(ms)`, `playBar(index)`; `timeupdate`, `barchange`, `ended`, `ready`, `error`.
- **Styling:** CSS custom properties for the marker colour and strength, `::part()` for the controls, slots so a site can bring its own controls.
- **Rendering:** pages as `<img>` (fast, cacheable, printable); the markers in an overlay positioned in percentages, so any page size works. Updates run on `requestAnimationFrame` while playing.
- **Accessibility:** keyboard play/pause/seek, the current bar announced politely, reduced motion respected, the pages' alt text settable.
- **Safety checks:** audio shorter than the last event's time → play without markers and warn ("Play repeats" was off); a sync map that fails to build → show the pages and the audio, no markers.

Open: whether the built-in controls show by default or only with `controls`.

## Rationale

Custom elements work in every modern browser and every framework, need no build step on the site, and can be dropped into a CMS page. The core stays usable on its own for sites that want their own player.

## Consequences

- The element is tested in real browsers (Playwright, DL-011), including Safari on iOS, Firefox and Chrome on Android before 1.0.
- Its API is public surface: once released, changes go through Changesets with semver (DL-012).
