## Context

The repository is public and meant for outside contributors, so the checks that keep it healthy must run automatically and be easy to run locally.

## Decision

- **TypeScript, strict:** `strict` plus `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` and `noImplicitOverride` (and the unused-code checks); no `any` (also a Biome error). `tsc --noEmit` runs in CI. TypeScript 7, the native compiler.
- **Biome** for lint and format (code, JSON and Markdown), no ESLint or Prettier; `biome ci` runs in CI.
- **Tests:** Vitest for the core; Playwright browser tests for the element once it exists. A **coverage floor of 90%** of lines, functions, branches and statements, enforced by Vitest's thresholds. The floor only goes up.
- **Size budget:** `scripts/check-size.mjs` checks the gzipped size of each built entry point against its budget (core: 4000 B; it was about 3.2 KB when set). The measured files are the readable `tsc` output, not a minified bundle.
- **Licence headers:** `scripts/check-spdx.mjs` (DL-007).
- **CI:** GitHub Actions on every push to `main` and every pull request, on Node 22 and 24. Third-party actions are pinned to commit SHAs, with the version in a comment. `npm run check` runs the same steps locally.
- The default branch is **`main`** (the DLD tooling uses `origin/main` as its base).

## Rationale

- The strict flags catch the index and optional-property mistakes that a parser over external files invites.
- Biome is one fast tool for both lint and format, with one configuration file.
- A coverage floor that only goes up keeps new code tested without forcing a number nobody can reach.
- A size budget makes an accidental dependency or a bloated change visible in review.
- Pinning actions to SHAs protects CI from a moved tag.

## Consequences

- Contributors need Node 22+ and nothing else; `npm install` brings every tool.
- Raising the size budget or lowering the coverage floor is a visible change in review.
