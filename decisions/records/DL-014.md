## Context

`<segno-player>` (DL-005) shows a score's SVG pages and draws the bar marker and note cursor (DL-006) over them. It has to work inside any site without the site's CSS breaking it, and without its CSS leaking into the site.

## Decision

The element renders into an **open shadow root**:

```
<div part="pages">                     one per player; focusable, with the keyboard shortcuts
  <div part="page">                    one per SVG page, positioned relative
    <img part="page-image">            the SVG page itself, from its URL
    <div class="overlay">              markers, positioned in percentages of the page
      <div class="bar-marker"> ×2      crossfading pair
      <div part="note-cursor">
<div part="controls-area">
  <slot name="controls">               a site's own controls; the built-in bar as fallback (DL-016)
<div class="live" aria-live="polite">  announcements for screen readers
```

- Pages are `<img>` elements loaded from the same URLs the site gives (fast, cacheable, printable, and the browser keeps them out of the main thread). The page's own size comes from its SVG `viewBox`; the image scales to the player's width.
- Each page has an overlay. A marker's box is the sync map's page fractions turned into `left`/`top`/`width`/`height` percentages, so markers stay on their bars at any size without measuring the DOM.
- The bar marker is a pair of elements that crossfade: on a bar change the current one fades out and the other moves to the new bar and fades in (or both switch at once with `bar-change="jump"`). The markers are moved between page overlays as playback crosses pages.
- Clicking a bar seeks to it (`barAtPoint`, then `seekTimeForBar`, DL-009).
- The page images get alt text from the `alt` attribute ("{alt}, page n of m"; "Page n of m" without it).
- Once the SVGs have been read, each page gets their aspect ratio, so the layout doesn't jump when the images arrive.

## Rationale

Shadow DOM isolates the player's markup and styles both ways while still letting sites theme it through custom properties and `::part()` (DL-015). Images are the cheapest way to show an SVG page; inlining SVG documents would bloat the DOM and expose the score's internals to the page's CSS. Percent-positioned overlays need no resize handling.

## Consequences

- Markers can't follow a page that a site restyles into another aspect ratio; pages keep their own ratio.
- `<img>` SVGs can't be styled or scripted; Segno never needs to.
