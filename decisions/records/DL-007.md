## Context

Segno is free software under the GPL version 3. The GPL comes in two forms: `GPL-3.0-only` and `GPL-3.0-or-later` (which also lets recipients use the code under any later version the FSF publishes). MuseScore itself is `GPL-3.0-only`. Segno contains no MuseScore code: it reads files MuseScore writes.

Sites that serve `<segno-player>` to their visitors distribute it, so its source has to be available to those visitors.

## Decision

- Everything in the repository is licensed **`GPL-3.0-or-later`**, with the full GPL v3 text in `LICENSE`.
- Every source file starts with an SPDX header, a copyright line and a link to the repository:

  ```ts
  // SPDX-License-Identifier: GPL-3.0-or-later
  // Copyright (C) 2026 The Segno contributors
  // https://github.com/jimutt/segno
  ```

  `scripts/check-spdx.mjs` checks the first line in CI.
- The npm package keeps its source readable: the published JavaScript is `tsc` output, not minified, with the TypeScript sources and source maps alongside, and every file carries the header above. The browser bundle, when there is one, starts with the same header.

## Rationale

- "Or later" is the FSF's recommended form and keeps Segno usable under a future GPL version without having to ask every contributor.
- It costs nothing in compatibility: `GPL-3.0-or-later` code can be combined with `GPL-3.0-only` code, the combination then being `GPL-3.0-only`. If MuseScore code were ever reused, the combination would become `GPL-3.0-only`, which is acceptable.
- Readable, linked files make the source obligation easy to meet for a site that serves the component: the source is in the very file it serves, and the link names the repository.

## Consequences

- Contributions are accepted under `GPL-3.0-or-later` (stated in CONTRIBUTING.md).
- Reusing MuseScore code would make that combination `GPL-3.0-only`; record a decision before doing so.
- Minifying the published files would weaken the readable-source guarantee; a minified bundle, if ever added, must ship next to the readable one.
